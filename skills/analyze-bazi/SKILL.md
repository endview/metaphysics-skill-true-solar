# 分析八字

把八字当作传统文化解释框架，不宣称它具有科学预测效力。先建立可复核的事实层，再给出有流派标签、置信度和现实替代解释的解读。凡从出生资料生成或核验命盘、计算起运，统一使用真太阳时；原始民用时间只作为不可覆盖的来源记录，不作为默认排盘时刻。

## 按条件读取引用

- 涉及任何天干属性或十神映射时，读取[十干与十神](references/ten-stems-and-ten-gods.md)。
- 涉及地支藏干或藏干十神时，读取[十二支藏干](references/branch-hidden-stems.md)。
- 涉及合、冲、害、三合、三会或重复支时，读取[干支关系表](references/relationships.md)。
- 需要从出生资料排盘、核盘、换算真太阳时、处理时辰/节气/换日边界，或确定大运方向与起运时间时，读取[排盘边界与起运流派](references/charting-boundaries.md)。
- 开始原局、大运流年、候选盘敏感性、历史核对或求职解读前，读取[分析工作流](references/analysis-workflow.md)。
- 涉及两人合盘、关系匹配或妻星/夫星时，读取[合盘协议](references/compatibility.md)。
- 组织最终答复或解释脚本 JSON 时，读取[输出契约](references/output-contract.md)。

## 建立输入与证据台账

把原始出生资料与给定命盘分开记录、分别评级；不要让一个等级替另一个背书。沿用[排盘边界与起运流派](references/charting-boundaries.md)中的 `B`（出生资料）与 `P`（命盘）等级。

1. 原样记录公历/农历声明、原始民用日期时间及精度、出生地点、经度、民用时区来源、历史时区/夏令时，以及用户给出的四柱、大运和流年。
2. 记录真太阳时换算工具/历算库、版本及访问日期、方程时差与经度修正；工具不分项输出时，记录其披露的等效参数。另存换算后的真太阳日期时间及时辰，不覆盖原始民用时间。
3. 标出缺失、近似、互相矛盾，以及换算后靠近时辰、换日或节气边界的项目；边界附近保留各合理候选盘。
4. 用户直接给出真太阳时或确认所给四柱按真太阳时生成时，记录 `verification_status=user_declared`，可按 `P0/P1` 谨慎解读并披露尚未独立核盘；只有可靠工具按披露参数独立换算、重排且一致，才可评为 `P2/tool_verified`。
5. 只有民用出生时而没有真太阳时结果时，先引导用户补充出生地区／经度和 IANA 时区，以便交给可靠工具换算；本轮没有换算能力时，也可请用户直接提供已换算日期时间或时辰。资料仍未解析时返回 `insufficient_input` 与最少 `follow_up_needed`，暂不进入依赖时刻的完整分析；不得手算、不得退回北京时间或其他民用时排盘。若存在边界候选，必须取得逐一对应的候选四柱再继续。

## 核验给定干支结构

对用户给出的四柱运行无第三方依赖的确定性检查器；按需加入所给大运、流年：

```bash
node scripts/inspect_bazi.mjs --pillars <年柱> <月柱> <日柱> <时柱> [--dayun <大运>] [--liunian <流年>]
```

把脚本输出限定为结构事实：日主、每个明干与藏干的十神、天干五合、地支六合/冲/害、完整三合/三会、重复支。它不从出生时间排盘，不检查四柱之间的历法一致性，也不判断合化、成局、旺衰或吉凶。命令与 JSON 字段见[输出契约](references/output-contract.md)。

## 先写事实层

在任何解释前列出：

1. 输入原文、`B/P` 等级、所用工具与参数、未决边界；
2. 四柱及所给大运/流年，明确哪些来自用户、哪些由外部工具生成；
3. 日主、明干、藏干及十神；
4. 脚本检出的关系存在性与涉及位置；
5. 候选盘之间不变和变化的事实。

不要把“存在合/冲”“出现某十神”等事实直接写成事件结论。不要把局部关系扩大成完整人生判断。

## 再写解释层

按[分析工作流](references/analysis-workflow.md)逐层分析，并保持以下四条互相独立：

- **旺衰**：声明采用的月令、通根、透干、扶抑等判据及反证。
- **调候**：单列寒暖燥湿和季节条件；不要把调候需要自动等同于旺衰用神。
- **格局**：注明具体流派、成格/破格条件和证据；证据不足就不定格。
- **用神**：先说明“用”服务于扶抑、调候、格局还是其他体系，再给结论；不同定义不得同名硬合并。

多流派并行呈现各自前提、结论和分歧，不投票、不硬融合，也不挑选最讨喜的一条。把置信度限制在命盘证据等级及流派稳定性允许的范围内。

## 处理原局、大运与流年

先完成原局，再把大运、流年作为新增时间层；不要用后来发生的事件倒改原局规则。起运计算须采用真太阳时出生时刻，并由可靠工具披露流派与关键参数；否则只分析用户明确给出的干支，不自造起止日期。

对候选盘分别运行同一流程，先写共同结论，再写对时柱、换日、节气或起运假设敏感的结论。若关键建议随候选盘改变，保留多方案并降低置信度。

## 冻结历史核对

把历史核对当作预先登记的对照流程，不当作润色故事的素材。在读取事件年份或结果前，冻结：候选盘、采用规则、预计领域/方向/时间窗、可证伪条件和置信度；随后逐项记录命中、部分命中和不命中，不改窗口、不增补象义。若事件已经全部可见，明确说明只能进行事后叙事核对；请求用户另留未披露的保留样本，或只把现有事件作为叙事背景。

## 转化为现实支持

求职或其他现实问题必须先回答可行动的现实层：目标岗位、证据材料、技能缺口、申请节奏、沟通与复盘。命理时间窗只能作为低置信度的反思提示，不能承诺录用、薪资或事件。不得用八字替雇主筛选、排序或拒绝候选人。

合盘必须遵守[合盘协议](references/compatibility.md)：先分别分析两盘，再分析互动；总置信度不得高于较弱一盘。仅在用户主动选择后使用妻星/夫星等传统视角，不依据姓名、性别或伴侣角色自行指定。
