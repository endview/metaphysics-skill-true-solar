# 玄学主路由：不补造缺失方法

仅在明确玄学请求、未指定方法而需要选法、或用户要求多方法时使用。普通职业、关系或生活建议不自动触发。

读取[能力登记](references/capability-registry.md)与[方法登记](references/method-registry.md)。正式编排读取[method-v5 契约](references/orchestration-contract.md)。四个 Skill 职责不变，主路由不复制或执行三个方法的算法，也不从原生载荷重新推导术数结论。

## 运行

本候选实现使用 `scripts/route.mjs` 的 method-v5。宿主以 `--method-root <bazi|ziwei|meihua> <实际安装绝对路径>` 登记子 Skill；路径是宿主配置，不从用户问事 JSON 中取得，不假设兄弟目录存在。缺包就明确 `unavailable`，不联网临时安装。旧 v4 材料只能只读审阅，不能改名升级成已验证 v5。

先完成对象、事件、命题、判断标准和每种方法的时间窗口绑定。`plan` 冻结全部分支后才开始计算；`run` 调用子方法。保留用户要求的方法清单，缺输入、未安装、不支持、执行失败分别展示。输入已齐不重复确认；不同方法所需资料不同，不为了凑齐组合而索取无关资料。

## 两阶段续接

子分支仅计算完成时，输出仍为部分完成。`branch_context` 取得指定分支的任务、事实、匹配知识卡与执行记录；由该方法上下文撰写草稿；`finalize_branch` 校验并续接交付。修订草稿复用原生结果，不再排盘或取数。不能把事实审阅算作用户要求的解释完成。

本地 Node 宿主没有独立语言模型上下文，必须显示 `blocked_isolation`，即使三种原生计算均运行成功。不得把进程、VM 或不同 branch ID 当成独立模型隔离。只有实际宿主适配器提供可核查的分支输入清单与观察记录、通过隔离验证，才比较已冻结的主张。

## 综合

只消费标准子结果的 claims。同对象、同事件、同命题、同判断标准、同时间尺度和完全相同的规范窗口/周期才可形式比较；重叠窗口、立春年与农历年不自动相等。条件相反保留冲突，方向不明保持不可比较，不多数投票，不换算法求一致。不同层面且共同现实目标可标互补，但不是互相证实。

最终保留 `requested_methods`、`completed_methods`、未完成原因、组合状态及来源。未完整覆盖原请求就是部分完成，不能事后缩小范围改称全部完成。缺紫微资料时交付已完成的八字并指出紫微未排；不要造宫位。

一个顶层请求只有一个活动路由。不得分派自身或让子 Skill 重开嵌套路由。健康、安全、强烈焦虑先处理现实需求，不推动反复占问。
