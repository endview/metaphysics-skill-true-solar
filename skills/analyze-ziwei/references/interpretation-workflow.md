# 解释工作流

## 1. 固定范围

先明确领域、时间层和用户期待的产出。V1 只处理本命、大限与流年，只回答事业、关系中的用户自身模式、迁移环境或阶段主轴；财务、田宅、疾厄只转译为相应的行为与规划主题。超出 V1 的时间层、领域或技法不自行扩展。

## 2. 建立输入链

按 `input-contract.md` 标注 `B/P` 等级、`time_basis=true_solar`、原始民用记录、`verification_status`、真太阳时换算来源／profile／版本、排盘来源、流派、四化表和边界参数。先确认出生与目标真太阳时均已解析；任一为 `unresolved` 时返回 `insufficient_input` 并引导换算或直接提供已换算结果，不使用民用时回退。`user_declared` 结果允许执行但保留未独立核验限制。存在合理候选盘时保留全部候选，不自动校时。

## 3. 冻结事实层

按 `facts-schema.md` 建立本命事实。只记录宫位、星曜、身宫、四化、三方四正与时间映射；不在事实层写性格、吉凶或事件。

先完成并冻结本命，再依次叠加大限和流年。后层只能说明关注重点如何变化，不得回写本命事实。

## 4. 选择目标宫与配置

从 `profiles.md` 选择一个主领域配置和必要时间层，再按 `domain-map.md` 选择目标宫。只加载支持该问题所需的相邻结构。

每个候选结论都使用同一证据框架：

```text
目标宫 → 三方四正 → 命/身背景 → 四化连接 → 大限 → 流年
```

若仅有单星、单宫、单一四化或一句古诀，不输出领域结论。

## 5. 构造正反证据

为每项结论分别写：

- 支持它的盘面结构；
- 削弱、限制或指向另一解释的结构；
- 结论成立需要的现实条件；
- 哪些已知事实与它不一致；
- 在不同候选盘下是否保持。

不同解释都满足规则时并列，不把含混词扩张成“都算对”，也不以叙事流畅度决定真假。

## 6. 叠加时间层

### 本命

描述较稳定的领域结构和可反思模式，不写终身定论。

### 大限

描述阶段资源重心、角色变化和适应任务。先说明它与本命哪些结构相接，再给阶段性含义。

### 流年

只说明目标真太阳日期所属农历流年周期内哪些主题更值得观察、哪些现实条件会放大或缓和它。目标 date-only 基准用于选定周期；profile 固定的引擎时辰仅作定位坐标，不把结论缩小为流月、流日、流时或确定事件，也不外推成完整公历年。

## 7. 比较候选盘

按 `candidate-sensitivity.md` 用同一问题、配置和事实模板比较。先写稳定项，再写敏感项；关键建议随候选盘反转时，标为不可判断。

## 8. 建立现实基线

在行动建议前列出当前现实证据，例如用户可控制的资源、已有行为、客观约束、专业信息和可观察结果。命盘只提供待观察的传统假设。

现实证据与命盘叙事冲突时：

1. 不修改盘面解释去迎合；
2. 不否定现实事实；
3. 以现实证据决定行动；
4. 把冲突列为降低结论强度的理由。

## 9. 转为行动

每个建议都应在不采信紫微斗数时仍然明确、可执行并可复盘。优先给用户自身能调整的沟通、规划、资料收集与复盘动作。

## 10. 语言过滤

保留必要技术名词，但将古籍解释转换为现代中性语言：

- 不用“克亲”“败家”“淫”“孤寡”“残疾”“贱”“小人”等词给人定性；
- 不把传统性别角色当作现实规范；
- 不把煞曜名称直接翻译成灾祸；
- 不把福祸词汇写成确定事实；
- 不用恐吓、羞辱或宿命措辞推动行动。

关键句使用“在所声明的传统规则下”“可作为观察主题”“若用于反思”等限定，并说明降低确定性的具体原因。
