# 候选盘敏感性

## 何时保留候选盘

出现以下任一情况时，不选定唯一盘：

- 工具核验或用户明确声明的真太阳时范围跨越时辰或换日边界，或子时换日口径不明；明确解析为一个不跨边界的真太阳时辰时，不因原始民用钟点靠近边界而额外生成候选；
- 原始民用日期时间、时区、历史 UTC offset、地点、经度或真太阳时换算来源存在合理候选；
- 不同可靠来源产生不同命宫、身宫、星曜、四化或运限映射；
- 同一排盘 profile 的可选参数会改变当前问题的关键结构；
- 命盘截图缺字或宫位信息不全。

## 候选标签

每张候选盘记录：

- 候选编号；
- 产生该盘的真太阳时选择器、换算来源／profile／版本和其他参数组合；
- 来源和 `B/P` 等级；
- 与其他候选不同的事实字段；
- 尚无法解决的原因。

不得用“较符合用户经历”作为升高等级的理由。

`birth.true_solar.status=candidate_set` 或 `target.true_solar.status=candidate_set` 表示一组已解析的边界候选，不代表概率分布；其 `verification_status` 必须随结果披露。`status=unresolved` 不是候选盘：它返回结构化 `insufficient_input` 和换算所需下一步，不能把 civil 时间当作一个临时候选。

## 比较步骤

1. 出生候选组内部使用同一出生换算 profile，目标候选组内部使用同一目标换算 profile；所有组合使用同一排盘 profile、流派配置、目标领域和时间层。出生与目标可分别披露不同的核验状态和来源。
2. 比较命宫、身宫、目标宫、三方四正、相关星曜及四化。
3. 分别叠加相同的大限和流年范围。
4. 提取所有候选共同支持的结论。
5. 标出强度变化、主题变化和方向相反之处。
6. 判断差异是否会改变现实行动。

只比较与当前问题有关的结构，避免为不相关星曜制造额外分支。

## 不同 profile 或流派

同一出生候选组内若使用不同出生换算 profile，或同一目标候选组内使用不同目标换算 profile，应拆成独立 profile 分支。不同排盘 profile 或流派也必须分别冻结输入与规则、独立生成事实层，再并列呈现；不得计算共同候选覆盖率，也不得用本页的稳定性标签把不同规则合成一张盘。

## 稳定性标签

| 标签 | 条件 | 输出方式 |
|---|---|---|
| 稳健 | 所有合理候选在领域方向和行动边界上相同 | 可输出共同结论，并保留输入限制 |
| 敏感 | 主题相同，但强度、阶段重点或解释路径不同 | 先写共同项，再并列差异，不给精细应期 |
| 不可判断 | 关键领域或行动建议在候选间相反，或必要事实缺失 | 不选赢家，只说明需要何种原始资料才能缩小范围 |

整体结论不得超过最弱相关候选的可信度。

## 禁止自动校时

不得根据性格印象、已知事件、关系经历、职业或用户偏好反向挑选出生时辰。这样会把解释结果重新当作输入，造成循环。

历史资料只能作为现实背景或帮助用户查找原始记录的线索，不能证明某张候选盘正确。用户后来取得出生证明、医院记录、家属一致记录或更可靠历算资料时，才更新输入等级并重新建立事实层。

## 输出最小化

只向用户展示：

- 产生分歧的关键参数；
- 稳定结论；
- 会改变理解或行动的差异；
- 当前最合理的下一步资料获取方式。

不要倾倒每张候选盘的全部宫星，也不要用更多解释掩盖无法确定。
