# 真太阳时排盘边界与起运流派

## 统一时间口径

从出生资料生成或核验四柱、计算大运起运时，一律采用真太阳时。原始民用日期时间必须原样保留为来源；不得以北京时间、当地民用时或地方平太阳时替代真太阳时结果。

真太阳时换算必须由可披露参数的可靠天文/历算工具完成。没有可靠工具、地点/经度或时区资料时返回资料不足，不手算修正，也不退回民用时排盘。

## 分层评级

分别记录两个等级，不相互替代：

| 代码 | 出生资料等级 |
|---|---|
| B0 | 未提供原始出生资料，只有命盘或结论 |
| B1 | 用户回忆或约略资料；时间、历法或地点至少一项不确定 |
| B2 | 用户声明为精确的原始民用日期时间、出生地点与时区；仍不表示真太阳时已经换算或命盘已经历法核定 |

| 代码 | 命盘等级 |
|---|---|
| P0 | 用户或第三方给定四柱，尚未独立检查或尚未确认真太阳时口径 |
| P1 | 干支字符、阴阳配对、十神与固定关系已由本 Skill 脚本做结构检查；不等同于真太阳时历法核盘 |
| P2 | 由能披露关键参数的可靠工具完成真太阳时换算并独立重排，且与给定盘一致 |

如果不同工具或参数产生不同盘，保持多个 `P1/P2-candidate`，不要强行选一个。解释置信度不得超过输入链最弱的相关等级。用户明确提供真太阳时或确认所给四柱使用该口径时，可标 `user_declared` 并按 `P0/P1` 谨慎解读；它不构成工具核验，不能升为 `P2`。

## 可靠排盘所需记录

原始记录与换算记录分开保存，至少包括：

- 工具或历算库名称、版本、访问日期及输出；
- 输入采用公历还是农历、闰月声明、原始民用日期时间及精度；
- 出生地点、经度、民用时区来源、历史时区与夏令时处理；
- 方程时差、经度修正；工具不分项输出时，记录其披露的等效换算参数；
- 换算后的真太阳日期时间及时辰；
- 年柱/月柱采用的节气边界及节气时刻来源；
- 日柱的换日规则，尤其是否以子初或子正换日；
- 时辰边界规则。

只有搜索摘要、无参数网页、模型记忆或手工心算，均不足以换算或标记 `P2`。本 Skill 的 `inspect_bazi.mjs` 不含真太阳时或历法引擎，不能从出生时间排盘。

## 候选关联结构

所有边界候选必须可以机械地关联“换算结果—参数—命盘”，不能用并列文字列表代替：

- `time_basis.resolution_status` 只用 `resolved`、`candidate_set`、`unresolved`。
- `time_basis.verification_status` 在 `resolved` 或 `candidate_set` 时只用 `tool_verified` 或 `user_declared`；`unresolved` 时固定为 `null`。它表示证据等级，不替代解析状态。
- `time_basis.resolved_candidates[]` 每项包含稳定的 `candidate_id`、`true_solar_datetime`、`true_solar_shichen`、`source_ref`、`conversion_parameters`、`boundary_reasons[]` 和 `chart_ref`。
- `chart_candidates[]` 每项包含稳定的 `chart_id`、对应 `candidate_id`、`four_pillars`、排盘来源／版本／访问日期，以及节气、换日、时辰与起运规则。
- `resolved` 必须恰有一个 resolved candidate；`candidate_set` 至少两个；`unresolved` 的 `resolved_candidates[]` 与 `chart_candidates[]` 都为空。
- `candidate_id` 与 `chart_id` 分别在各自数组内唯一。每个 `resolved_candidates[].chart_ref` 必须命中且只命中一个 `chart_candidates[].chart_id`，两项的 `candidate_id` 必须相同；不得存在无对应换算候选的命盘或无对应命盘的换算候选。
- 事实与主张的依据通过这些稳定 ID 引用，不靠数组位置猜测。

## 边界敏感性

真太阳时结果靠近时辰、换日或节气边界，或原始时刻靠近历史时区变更边界时：

1. 不用心算擅自选择一侧；
2. 用可靠工具按时间精度、换算误差与各合理规则生成候选盘，或让用户提供候选盘；
3. 保留每个候选盘的参数标签；
4. 分别检查并比较事实、共同结论和分歧；
5. 若实际建议随候选盘改变，降低置信度并保留多方案。

## 大运方向与起运

不同传统对顺逆、以年干或其他基准、从节还是气计算、出生到前一/后一节气的换算、虚岁/周岁和交运落点存在差异。不要把一种算法称为唯一规则。

需要计算大运时，先让用户选择流派或由可靠工具明确展示算法；以换算后的真太阳时出生时刻为基准，并使出生时刻与目标节气时刻处在工具声明的一致时间基准下。记录顺逆依据、目标节气精确时刻及来源、时间差换算规则和首运起点。条件缺失时返回资料不足；用户另给大运干支时只能按其来源等级分析，不自行添加起运年龄或公历起止年。
