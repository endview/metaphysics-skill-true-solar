# 起卦协议

## 版本原则

- `lunar-time-v2` 与 `numbers-v2` 是不可就地改义的协议标识；两者都显式接受 `civil` 或 `true_solar` 时间口径。旧 `v1` 输入契约不再调用。
- 同一问题、同一观察期限只保留首次有效结果。不得为了满意、一致或更“吉”而重复起卦。
- 起卦前固定问题、观察期限、应期单位、应期规则、`time_basis`、IANA 时区和方法。数字法还要固定原始数字及顺序；看到结果后不得切换口径。
- `civil` 要求恰好一个 `--datetime` 或 `--now`。指定时点使用 RFC 3339 profile：`YYYY-MM-DDTHH:MM:SS[.fraction]Z` 或带 `±HH:MM` 偏移；逐字段验证日期与钟点，并确认偏移能在指定 IANA 时区投影出相同钟面。`--now` 只用于民用时，执行后立即以输出的 instant 与当地钟面冻结。
- `true_solar` 要求原始 `--civil-datetime`、`--true-solar-local-datetime`、IANA 时区、地点、经度与换算来源。原始民用时按上述 RFC 3339 规则验证；真太阳钟面固定为无偏移的 `YYYY-MM-DDTHH:MM:SS`，表示连续当地太阳钟，不是物理 instant，不做 IANA 夏令时缺口或重复时段投影验证。
- 经度使用十进制度且东正西负；换算来源必须能识别具体工具／服务及版本或结果引用。脚本只验证来源已记录，不判断其可靠性，也不计算或近似真太阳时。若可靠来源无法给出唯一换日或时支候选，调用方先冻结一个；无法冻结就返回 `insufficient_input`，不得执行脚本。
- `conversion.wallClockShiftSeconds` 按真太阳钟面字段减民用当地钟面字段计算，跨日期并忽略 UTC offset 变化；它不是两个 physical instant 的差。
- 输出保留协议标识、所选口径及其来源、原始输入、中间算式、原始余数、余零映射和 Node／ICU／CLDR／时区资料；运行时变化可能造成历法差异，不得隐去。

## 公共约定

使用先天八卦数：

| 数 | 经卦 | 三爻（自下而上） | 五行 |
|---:|---|---|---|
| 1 | 乾 ☰ | 阳阳阳 | 金 |
| 2 | 兑 ☱ | 阳阳阴 | 金 |
| 3 | 离 ☲ | 阳阴阳 | 火 |
| 4 | 震 ☳ | 阳阴阴 | 木 |
| 5 | 巽 ☴ | 阴阳阳 | 木 |
| 6 | 坎 ☵ | 阴阳阴 | 水 |
| 7 | 艮 ☶ | 阴阴阳 | 土 |
| 8 | 坤 ☷ | 阴阴阴 | 土 |

取八卦数时先计算非负余数 `r = n mod 8`，`r = 0` 映射为 8；取动爻时 `r = n mod 6`，`r = 0` 映射为 6。必须同时记录原始余数与映射后数值。

六爻始终从下往上编号 1 至 6：下卦为第 1–3 爻，上卦为第 4–6 爻。动爻所在经卦为用，另一静卦为体。

派生卦统一从本卦六爻计算：

- 变卦：只反转动爻阴阳。
- 互卦：本卦第 2、3、4 爻组成下互卦，第 3、4、5 爻组成上互卦，内部仍按自下而上排列。
- 错卦：本卦六爻逐爻阴阳反转。
- 综卦：本卦六爻次序完全倒转。

## `lunar-time-v2`

1. `civil` 使用冻结 instant 在指定 IANA 时区投影出的当地日期与小时；`true_solar` 使用外部来源给出的连续真太阳当地日期与小时。未选口径只作来源，不参与计算。
2. 为避免把真太阳钟面伪装成 instant，也避免夏令时缺口，以所选当地公历日期的 UTC 正午作为只承载日期的 `calendarCarrier`，再由 Node `Intl.DateTimeFormat` 的 `chinese` calendar 取得 `relatedYear`、农历月与农历日。该 carrier 不是起卦时点；时支直接读取所选当地小时。
3. 闰月沿用其数字月序，另记 `isLeapMonth: true`，不额外加一或改序。
4. 年支数由农历 `relatedYear` 计算：子=1、丑=2、…、亥=12；公历／农历年号 2020 对应子年。实现式为 `mod(relatedYear - 4, 12) + 1`。
5. 时支数按所选口径的当地钟点：23:00–00:59 子=1，01:00–02:59 丑=2，依次至 21:00–22:59 亥=12。
6. 上卦原值 = 年支数 + 农历月数 + 农历日数。
7. 下卦原值 = 年支数 + 农历月数 + 农历日数 + 时支数。
8. 动爻原值与下卦原值相同。
9. 上、下卦分别按余八规则映射，动爻按余六规则映射。

`Intl` 和 UTC 正午日期 carrier 是此协议的一部分，不可用第三方农历库或另一个 instant 静默替换。若运行环境不支持 Chinese calendar、月份字段无法解析或 IANA 时区无效，必须失败并停止。

## `numbers-v2`

数字规则不读取时点参与取数，但个案仍须满足所选 `civil` 或 `true_solar` 输入契约，并在结果中保留相应时间上下文。

只接受保持原顺序的正安全整数：

- 两数 `[a, b]`：`a` 为上卦原值，`b` 为下卦原值，`a + b` 为动爻原值；`a + b` 也必须是安全整数，否则停止且不计算余数。
- 三数 `[a, b, c]`：`a` 为上卦原值，`b` 为下卦原值，`c` 为动爻原值。

不要对数字排序、拆位、相加各位、取绝对值或补随机数。两数与三数规则不混用。

## 体用五行关系

五行相生：木→火→土→金→水→木。五行相克：木→土→水→火→金→木。

以体为参照只输出以下五类之一：`比和`、`体生用`、`用生体`、`体克用`、`用克体`。它描述协议内的象征关系，不是成败概率或现实因果。
