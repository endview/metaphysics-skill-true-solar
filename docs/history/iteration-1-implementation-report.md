## 2. 本轮实际实现

### 个案、时间和执行

实现会话内 subject/event/case/task 标识、冻结输入、任务级状态、同事件执行锁与计算后登记。重复开始复用同一个成功结果；技术重试必须有原因且输入摘要不变。新建 case ID 不能绕过同一已登记事件的冻结。

实现历史指定时点与当前时点分离；时钟在显式冻结时只读一次；保留分钟精度；校验数字偏移与 IANA 时区一致性；保留 DST 重复时段候选，拒绝不存在时刻。区分固定 24 小时日与当地日历日。真太阳时只提供来源检查接口，不进行天文换算，不把太阳钟面时间直接当成民用瞬时。

实现由代码登记的固定子进程入口、文件摘要、输入标准输入传递、环境变量最小化、输入输出大小限制与超时。退出状态、原始输出摘要、规范化载荷摘要、环境及尝试次数形成执行记录。来源等级固定为 `local_runner_observed`，不接受上传或原生 JSON 自报的宿主认证。

### 解释、路由和打包检查

计算完成不自动产生解释。必须另行提交解释草稿，校验绑定、状态、依据引用、事实文字及选定知识卡的结构/前置条件。解释失败只修订草稿，不重算。事实文本由确定性渲染器产生，篡改数字会被拒绝。

相对阶段不能附加具体日期字段或在已覆盖的文本形式中伪装成日期；计数必须沿用冻结单位、引用原生字段并处于实际观察窗口内。实现在已登记测试范围内的隐藏事实、概率和确定性措辞风险检查，但没有声称穷尽自然语言语义。

路由保存请求方法与已完成方法。没有验证独立模型上下文时，即使两个脚本都成功，也只保留分支信息，不形成“独立两法核验”。比较要求对象、事件、命题、判断标准、窗口及时间层一致；重叠窗口不等于相同窗口。

提供正式包目录的允许清单检查，能拒绝未登记文件、软链接、测试夹具、日志、明显密钥标记和兄弟 Skill 路径依赖。这不是完整隐私扫描，也没有实际构建四个原 Skill 包。

## 5. 关键缺口与边界

1. 不能把 `fixture.echo`、`synthetic.standard-child.v1` 或 `syntheticCard()` 当成真实方法、旧契约兼容实现或传统解释来源。
2. 对同一登记事件的锁可以程序检查，但不能识别用户用全新对象/事件标识重述同一现实事件。语义识别和确认仍是宿主/Skill 层责任。
3. 记录保存在当前进程；不能保证进程重启、记录失联或多进程间的去重。纠错会保留原记录并使结果失效，但不会自动安排重新起卦。
4. 来源/知识卡元数据完整不代表其真实性已经获得独立认证。JSON Schema 文件是候选描述，真实原生及旧标准子结果仍须接入其原有完整校验。
5. 风险正则只能覆盖已定义形式；没有独立人工审查或模型对话回归，不能声称语义行为零违规。
6. 固定入口、摘要和进程限制不构成执行任意不可信代码的安全沙箱；只应登记已审查脚本。
7. 当前只实测 Linux / 指定 Node 环境。Windows、macOS、其他 Node/ICU 组合均未验证。
8. 原生 CLI 参数、八字来源路径、紫微懒加载、引擎校验和梅花算法一律没有根据描述自行重写。
