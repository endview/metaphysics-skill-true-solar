# 本轮运行边界与证据分级

## 证据能说明什么

执行器对自己产生的记录使用 `local_runner_observed`。它没有认证宿主工具轨迹的接口，原生输出或外部 JSON 中出现 `host_observed` 不会被采信。对话工具确实观察到了本轮测试执行，但不能因此给未来导入记录或术数计算统一升级证据等级。

源码摘要可发现版本或内容变化，不能证明源码没有恶意，也不能证明输入是真实出生资料。输出摘要可发现篡改，不能证明解释与现实相符。

## 能力探测的保守返回

`detectCapabilities()` 将 Node 进程能力与文件读取分别描述。Chinese calendar 的 API 即使存在，也只记录存在，正确性等级仍为 `unknown`；模型分支隔离为 `unavailable`。没有提供用用户 JSON 覆盖成 verified 的开关。

## 个案与时间

状态仅存在于 `SessionCaseStore` 内。对同一登记事件的重复开始、冻结后改窗口、技术重试和多个预冻结 case 的竞态有明确处理；全新语义伪装、跨进程状态、长期授权存储仍未覆盖。注册新的 event 必须说明差别，但代码不声称能证明自然语言差别真实成立。

日期规范化输出中的 UTC 时间表示的是瞬时，来源时区仍保留。外部请求必须提交明确日期、偏移和时区；未实现“下周”等任意自然语言期限解析。固定 24 小时与当地日历日明确区分。历史特殊的秒级时区偏移等未覆盖形式会拒绝，不静默近似。

真太阳时来源接口只验证声明或工具元数据是否齐全；`tool_verified` 声明需要真实已审查适配器才能采用，不因这个函数返回而完成认证。本轮没有天文换算、节气排盘或出生事件反选命盘。

## 解释与安全

知识卡结构检查不等于外部来源真实性审查。调用方只能从已审查资源登记知识卡，不得把模型生成的 `review_status` 当成审查证据。当前卡片只在合成测试中存在。

确定性事实、主张引用和精度约束可程序检查，但任意自然语言的隐含意义不能。风险模式属于防错辅助，不是完整的读心/事后拟合检测器。`semantic_review=not_performed` 始终保留，正式发布不能依据本轮测试自动放行。

进程使用固定 Node 入口、临时工作目录、标准输入、输入输出限制、超时与精简环境变量。Linux 上尝试终止同一进程组；Windows 上的后代进程管理未验证。这不是防恶意代码的沙箱，不应登记不可信脚本。

包检查器能够发现已列出的目录与文件违规，但不能发现所有个人数据或密钥。最终人工隐私、许可证与真实安装审查仍然必需。
