## 原则

只收集当前问题所需资料。把原始出生记录、真太阳时换算、命盘来源、排盘参数和现实背景分开保存；任何一层不确定，都不得由另一层补成确定事实。

本 Skill 统一使用真太阳时，接受两种入口：

1. 用户提供明确声明 `time_basis=true_solar` 且来源可追溯的完整紫微命盘；
2. 用户提供原始民用出生记录，并由可靠外部来源解析真太阳时后交给内置 CLI 排盘。

民用日期时间只作来源记录，不能作为引擎选择器。模型记忆、搜索摘要、无参数网页、手工心算或未经验证的近似太阳公式不足以建立可靠换算。换算缺失时返回 `insufficient_input`，不得回退民用时，也不得根据人生经历自动校时。

## 来源等级

### 出生资料等级

| 代码 | 定义 |
|---|---|
| `B0` | 没有原始出生资料，只有命盘截图、宫位表或既有结论 |
| `B1` | 原始日期时间、地点、时区、经度、换算来源或已解析真太阳时至少一项约略、候选或不确定 |
| `B2` | 原始民用日期时间、地点、IANA 时区和经度明确；真太阳时是否已解析由独立的 `true_solar.status` 表示，仍不等于命盘已经核定 |

### 命盘等级

| 代码 | 定义 |
|---|---|
| `P0` | 命盘或宫位资料由用户／第三方给定，来源、参数或真太阳时口径不完整 |
| `P1` | 命盘字段完整，真太阳时来源、流派和主要排盘参数可追溯，但未与第二个可靠来源核对 |
| `P2` | 同一排盘协议下由两个相互独立、可追溯的来源得到一致结构；单一工具即使完整披露参数也仍为 `P1` |

解释可信度不得高于相关输入链中较弱的等级。`B0` 只允许转录给定命盘中可见字段；命盘未明确真太阳时口径时只能记为 `P0`，不得形成本 Skill 的正式领域结论，也不能反推出生资料正确。

## 原始民用记录

出生资料必须记录：

- 原始公历日期和当地民用时间；只有农历记录时，先由可追溯历法来源解析为公历民用记录；
- 时间精度以及出生记录来源；
- 出生地点、经度与对应 IANA 时区；
- 可得时记录历史 UTC offset／夏令时依据；
- 排盘体系要求的算法性别参数；该参数只用于所声明的传统算法，不推断性别认同；
- 换日和晚子时规则。

不需要姓名、证件号码、详细住址、联系方式或其他无关身份信息。

## 真太阳时换算记录

出生和目标基准分别使用 `true_solar` 对象：

| 字段 | 约束 |
|---|---|
| `status` | `resolved`、`candidate_set` 或 `unresolved` |
| `verification_status` | `tool_verified` 或 `user_declared`；后者可执行但必须保留未独立核验限制 |
| `conversion_source.provider` | 工具来源名称；用户声明固定为 `user` |
| `conversion_source.profile_id` | 工具核验时必填；用户声明时可为 `null` 或 `unspecified` |
| `conversion_source.version` | 工具核验时必须是具体版本；用户声明时可为 `null` 或 `unspecified` |
| `conversion_source.access_date` | 可选访问日期／标识；用户声明时可为 `null` 或 `unspecified` |
| `conversion_source.reference` | 可选的定位信息；不得放无关个人资料 |
| `resolved_candidates` | 已解析选择器数组；每项含稳定 `selector_id` 和真太阳日期 |

`resolved` 必须恰有一个选择器；`candidate_set` 至少有两个；两者都必须声明 `verification_status`。`unresolved` 不得伪造核验状态、来源或结果。只给 civil 记录时可省略 `true_solar`，CLI 将其规范化为 `unresolved`，返回 `status=insufficient_input`、`missing_fields` 与 `follow_up_needed`；它不会调用排盘引擎，也不能读取民用字段代替。用户直接提供已换算结果时用 `verification_status=user_declared`；`conversion_source` 可省略并规范化为 `provider=user`、其他来源字段为 `null`，不得描述成工具已核验。可靠工具结果用 `tool_verified` 并强制具体 profile 与版本。

出生选择器还必须在每项中二选一提供：

- 真太阳 `local_time`，由 CLI 映射为时辰；或
- 已解析 `time_index`，使用 0 至 12：0 为早子时，1 至 11 依次为丑至亥时，12 为晚子时。

接近时辰或换日边界时，工具核验结果或用户明确声明可给出多个候选，各自保留真太阳日期与时间／时辰及 `verification_status`；不得先合并成单一时辰。

## 内置 CLI：`ziwei.input.v2`

在 Skill 根目录执行 `node scripts/ziwei-cli.mjs`。根对象只接受 `schema_version`、`profile_id`、`birth` 和 `target`：

| 字段 | 约束 |
|---|---|
| `schema_version` | 固定为 `ziwei.input.v2` |
| `profile_id` | 必填且固定为 `ziwei-core-true-solar-v2` |
| `birth.gender` / `algorithm_gender` | 二选一；只接受算法所需的 `male/female` 或 `男/女` |
| `birth.source_grade` | `B1` 或 `B2`；省略时保守记为 `B1`；只描述原始出生记录，不替代真太阳时解析状态 |
| `birth.civil` | 原始公历 `date`、`local_time`、IANA `timezone`、可选 `utc_offset`，以及含 `name` 与 `longitude_deg` 的 `location` |
| `birth.true_solar` | 状态、`verification_status` 和一个或多个已解析出生选择器；工具核验时另含来源／profile／版本 |
| 晚子时 | 可选 `late_zi_policy` 或 `late_zi_policy_candidates`；只用 `current` 或 `forward` |
| `target.civil` | 原始公历 `date`、IANA `timezone`、可选 `utc_offset`及地点／经度；当前版本是 date-only，不收集人为目标时刻 |
| `target.true_solar` | 状态、`verification_status` 和一个或多个 date-only 真太阳日期选择器；工具核验时另含来源／profile／版本 |

目标真太阳日期只用于确定大限与其所属农历流年周期。引擎接口所需的目标时辰由 profile 固定为定位坐标，不代表用户提供的时刻，不得解释为流日或流时。

候选笛卡尔积最多 64 组。任一候选目标真太阳日期不得早于对应的出生候选公历日，并须落在有效大限范围内。纯本命问题仍要给出目标真太阳日期以满足三层事实生成，但解释时只读取 `origin`。

`ziwei-core-true-solar-v2` 以农历正月初一切换流年。同一公历年在农历新年前后属于两个流年周期；用户只说某公历年时，不得任取一天代表全年，应追问目标日期／农历流年，或在可靠历法确定边界后明确分段。

## 命盘最小字段

完整结构性本命分析至少需要十二宫宫名与宫位、命宫／身宫／五行局、主星及实际使用的辅煞曜、生年四化、流派与四化表、排盘来源和真太阳时口径。缺失或模糊字段必须显式保留。

加入大限时，还需要大限顺序、年龄／年份范围、宫位映射和该层四化规则。加入流年时，还需要明确的目标真太阳日期或农历流年周期、年龄口径、流年宫位映射及该层四化。当前版本不接入小限、流月、流日或流时。

## 问题字段

记录用户要理解的领域、阶段或年份、可控制的选择、已知现实事实与希望得到的输出类型。问题未具体到可行动层面时，只追问一个最能缩小范围的信息；不得为追求完整命盘收集无关隐私。

## 边界与候选盘

以下情况保留候选，不强选单盘：

- 可靠换算给出跨时辰或换日的真太阳时选择器；
- 原始日期时间、时区、历史 UTC offset、地点或经度不确定；
- 同一 profile 的可追溯来源生成不同命宫、身宫、星曜或四化；
- 参数差异会改变当前问题的关键结构。

每个候选须带独立参数标签。同一出生候选组只使用一个出生换算 profile，同一目标候选组只使用一个目标换算 profile；出生与目标可分别使用不同来源。不同排盘 profile 或流派不放进同一候选集合。具体比较见 `candidate-sensitivity.md`。

## 第三方资料

分析关系时优先只分析用户自身互动倾向。若确需另一人的命盘，确认用户有权使用其资料并最小化字段；输出仍限定为与用户相关的互动结构，不扩展未公开的个人信息。
